# 系统架构

## 整体架构

系统采用 **六层架构** 设计，从外到内依次为：

```
┌──────────────────────────────────────────────────────────────┐
│                     API 层 (api/)                             │
│              FastAPI 路由 · 请求/响应 Schema                  │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│                    服务层 (service/)                          │
│               DialogueService · 编排核心流程                    │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│                    引擎层 (engine/)                           │
│         DialogueEngine · Builder · 系统组件组装                │
└──────┬──────────┬──────────┬──────────┬──────────────────────┘
       │          │          │          │
┌──────▼──┐ ┌─────▼─────┐ ┌─▼────────┐ ┌▼──────────────┐
│ 规划层  │ │ 任务层    │ │ 知识层    │ │ 闲聊/澄清层   │
│ plan/   │ │ task/     │ │knowledge/ │ │ chitchat/     │
│         │ │           │ │           │ │ clarify/      │
└─────────┘ └─────┬─────┘ └──────────┘ └───────────────┘
                  │
          ┌───────┴────────┐
          │  动作层        │
          │ task/action/   │
          │ · builtin/     │
          │ · custom/      │
          └───────┬────────┘
                  │
┌─────────────────▼────────────────────────────────────────────┐
│                  基础设施层 (infrastructure/)                  │
│      LLM · 数据库 · HTTP 客户端 · 配置管理                    │
└──────────────────────────────────────────────────────────────┘
```

## 架构分层详解

### 1. API 层 (`atguigu/api/`)
- **职责**：接收 HTTP 请求、参数校验、数据序列化/反序列化
- **核心组件**：FastAPI `app`、路由 `chat_router`、Pydantic Schema
- **端点**：`POST /api/chat`、`GET /api/chat/history`

### 2. 服务层 (`atguigu/service/`)
- **职责**：协调引擎与数据仓库，封装对话处理的完整事务
- **核心组件**：`DialogueService`
- **流程**：加载对话状态 → 调用引擎处理消息 → 持久化更新后的状态

### 3. 引擎层 (`atguigu/engine/`)
- **职责**：对话消息的智能路由，系统组件组装
- **核心组件**：`DialogueEngine`、`build_dialogue_engine()`
- **能力**：会话管理、回合生命周期、消息路由分发

### 4. 规划层 (`atguigu/plan/`)
- **职责**：分析用户输入，决定当前回合的应答策略
- **核心组件**：`TurnPlanner`、`TurnPlanValidator`
- **决策路径**：`task` → `knowledge` → `chitchat` → `clarify`

### 5. 任务层 (`atguigu/task/`)
- **职责**：执行业务流程，管理对话状态变更
- **核心组件**：`TaskHandler`、`FlowExecutor`、`CommandProcessor`
- **子模块**：命令(Command)、流程(Flow)、动作(Action)

### 6. 知识层 (`atguigu/knowledge/`)
- **职责**：识别知识查询意图，从多源检索信息并生成应答
- **核心组件**：`KnowledgeHandler`、`KnowledgeProvider`、`KnowledgeResponder`

### 7. 闲聊/澄清层 (`atguigu/chitchat/`、`atguigu/clarify/`)
- **职责**：处理非任务型对话和意图不明确时的澄清

### 8. 基础设施层 (`atguigu/infrastructure/`)
- **职责**：提供 LLM 调用、数据库连接、HTTP 客户端等底层能力
- **核心组件**：`llm` (LangChain 模型)、`database` (异步引擎工厂)、`http_client` (httpx)

       │     │     │      │    │

## 设计要点

### 1. 回合规划 (Turn Planning)
每条用户消息都经过 LLM 规划，输出结构化的 `TurnPlan`，包含任务、知识、闲聊三个赛道之一的指示。验证器确保只有一个赛道被选中。

### 2. 状态管理
- 对话状态（`DialogueState`）按 `sender_id` 独立存储
- 支持多会话（Session）、会话超时（1小时无活动自动关闭）
- 任务可被中断和恢复，支持多任务堆栈（`paused_tasks`）

### 3. 流程执行 (Flow Execution)
- 流程以 YAML 文件定义，支持声明式步骤编排
- 收集(Collect)步骤自动尝试从聚焦对象(Focused Object)填充 Slot
- 动作(Action)是原子执行单元，注册后可被流程引用

### 4. 对象消息
用户可发送结构化对象（如订单卡片、商品卡片），系统自动识别并映射到当前等待的 Slot。
