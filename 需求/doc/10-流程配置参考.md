# 流程配置参考

## 概述

流程配置文件是系统的核心业务编排描述文件，使用 YAML 格式定义。系统支持两类流程文件：
- **user_flows.yml**：用户侧业务流程
- **system_flows.yml**：系统侧流程

## 文件结构

### 顶层结构

```yaml
slots:          # 全局 Slot 定义（可选）
  slot_name:
    type: text
    label: 展示名称
    description: 描述

flows:          # 流程定义列表
  flow_id:
    name: 流程名称
    description: 流程描述
    steps:
      - id: step_id
        type: start|action|collect|end
        # ...
```

### Slot 定义（`slots`）

在 YAML 顶层定义的 Slot 可在流程中通过 `slot_name` 引用，主要用于 `CollectSlotStep`。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | `string` | 是 | 数据类型（当前固定为 `text`） |
| `label` | `string` | 是 | 展示名称 |
| `description` | `string` | 否 | 描述 |

**示例**：

```yaml
slots:
  order_number:
    type: text
    label: 订单号
    description: 用户的订单号

  product_id:
    type: text
    label: 商品ID
    description: 当前咨询商品的唯一标识
```

### 流程定义（`flows`）

#### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `string` | (键) | 流程唯一标识 |
| `name` | `string` | 是 | 流程展示名称 |
| `description` | `string` | 是 | 流程功能描述 |
| `steps` | `list` | 是 | 步骤列表 |

## 步骤定义

### 通用字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `string` | 是 | 步骤唯一标识（流程内唯一） |
| `type` | `string` | 是 | 步骤类型：`start` / `action` / `collect` / `end` |
| `next` | `string` 或 `list` | 是 | 下一步跳转，见下方"跳转规则" |

### 1. Start 步骤 (`type: start`)

流程的起始步骤，每个流程必须有且仅有一个。

```yaml
- id: start
  type: start
  next: next_step_id
```

### 2. Action 步骤 (`type: action`)

执行一个已注册的动作。

```yaml
- id: step_id
  type: action
  action: action_name           # 动作名称
  args:                         # 动作参数（可选）
    key: value
    # 支持 Jinja2 模板语法
    text: "订单{{ slots.order_number }}状态：{{ slots.order_status }}"
    mode: static
  next: next_step_id
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | `string` | 是 | 动作名称（引用 ActionRegistry） |
| `args` | `dict` | 否 | 动作参数，值支持 Jinja2 模板 |

**内置动作列表**：

| 动作名称 | 说明 |
|----------|------|
| `action_listen` | 等待用户输入（暂停流程） |
| `action_response` | 生成回复，支持 mode: static / rephrase / llm |

自定义动作见[动作系统文档](./06-动作系统.md)。

### 3. Collect 步骤 (`type: collect`)

收集用户的输入信息。

```yaml
- id: step_id
  type: collect
  slot_name: order_number       # 要收集的 Slot 名称
  response:                     # 询问用户的回复
    text: "请告诉我你的订单号。"
  next: next_step_id
  validation: "value and len(value) == 6"  # 验证条件（可选）
  failure_response:                        # 验证失败回复（可选）
    text: "订单号格式不正确，请重新输入6位数字订单号。"
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `slot_name` | `string` | 是 | 引用的 Slot 名称（须在 `slots` 区定义） |
| `response` | `dict` | 是 | 询问用户的回复配置，必须包含 `text` 字段 |
| `validation` | `string` | 否 | Python 表达式验证条件，作用域含 `value` / `slots` / `context` |
| `failure_response` | `dict` | 否 | 验证失败时的回复，必须包含 `text` 字段 |

### 4. End 步骤 (`type: end`)

流程结束步骤。

```yaml
- id: end
  type: end
  next: []
```

> `next` 必须为空列表 `[]`。

## 跳转规则

### 静态跳转（字符串）

```yaml
next: next_step_id
```
直接跳转到指定步骤。

### 条件跳转（列表）

```yaml
next:
  - if: "slots.get('product_id')"     # 条件表达式
    then: respond                      # 满足时跳转
  - else: missing_product_context      # 兜底跳转
```

| 子字段 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `if` | `string` | 否 | Python 条件表达式（作用域含 `slots`、`context`） |
| `then` | `string` | 是（配合 `if`） | 条件成立时跳转到的步骤 ID |
| `else` | `string` | 否 | 所有条件都不满足时的兜底跳转 |

### 条件表达式

- 使用 Python `eval()` 执行
- 可用的变量：
  - `slots` — 当前任务的 Slot 字典（`dict`）
  - `context` — 当前步骤上下文（`dict`）
  - `value` — 仅在验证表达式中可用，代表用户输入的值
- **注意**：`eval()` 执行任意 Python 表达式，需确保表达式来源可信

### 执行逻辑

```
1. 遍历条件列表
2. 对每个 if 条件：
   - eval(condition) 结果为 True → 跳转到对应的 then
   - 结果为 False → 检查下一个条件
3. 没有条件匹配时：
   - 如果存在 else → 跳转到 else 目标
   - 如果不存在 else → 报错
```

## 完整示例

### 订单状态查询

```yaml
order_status_query:
  name: 订单状态查询
  description: 帮用户查询订单当前的处理状态
  steps:
    - id: start
      type: start
      next: ask_order_number

    - id: ask_order_number
      type: collect
      slot_name: order_number
      response:
        text: "请告诉我你的订单号。"
      next: lookup_order_status

    - id: lookup_order_status
      type: action
      action: action_lookup_order_status
      next: show_order_status

    - id: show_order_status
      type: action
      action: action_response
      args:
        mode: static
        text: "订单{{ slots.order_number }}当前状态是：{{ slots.order_status }}。{{ slots.order_summary }}"
      next: end

    - id: end
      type: end
      next: []
```

### 相似商品推荐（含条件分支）

```yaml
similar_product_recommendation:
  name: 相似商品推荐
  description: 基于当前商品为用户推荐类似商品
  steps:
    - id: start
      type: start
      next:
        - if: "slots.get('product_id')"
          then: respond
        - else: missing_product_context

    - id: missing_product_context
      type: action
      action: action_response
      args:
        text: "请先选择一个商品，再继续咨询。"
      next: end

    - id: respond
      type: action
      action: action_recommend_similar_products
      next: end

    - id: end
      type: end
      next: []
```

## 模板语法

在 Action 步骤的 `args.text` 和 `args.prompt` 中支持 Jinja2 模板语法：

| 变量 | 说明 | 可用场景 |
|------|------|----------|
| `{{ slots.slot_name }}` | 当前流程 Slot 值 | args.text, args.prompt |
| `{{ context.field }}` | 系统任务上下文 | args.text (系统流程) |
| `{{ history }}` | 对话历史 | args.prompt (rephrase/llm 模式) |
| `{{ user_message }}` | 当前用户消息 | args.prompt (rephrase/llm 模式) |
| `{{ current_response }}` | 建议回复文本 | args.prompt (rephrase 模式) |
