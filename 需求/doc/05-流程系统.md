# 流程系统

## 概述

流程系统是系统的业务编排引擎，通过声明式的 YAML 配置定义业务流程，支持步骤跳转、条件分支、Slot 收集和动作执行。运行时由 `FlowExecutor` 负责按步骤推进。

## 核心组件

```
task/flow/
├── models.py          # Flow、FlowSlot、FlowsList 数据模型
├── steps.py           # FlowStep 及其子类型（Start/Action/Collect/End）
├── links.py           # FlowStepLink 及其子类型（Static/Conditional/Fallback）
├── loader.py          # YAML → FlowsList 的加载/解析
└── executor.py        # 流程执行引擎
```

## 流程定义结构

### YAML 格式

```yaml
slots:
  slot_name:
    type: text           # 参数类型
    label: 订单号         # 展示标签
    description: 用户的订单号  # 描述

flows:
  flow_id:
    name: 流程名称
    description: 流程描述
    steps:
      - id: step_id
        type: start|action|collect|end
        # ... 各类型特有字段 ...
        next: next_step_id   # 下一步（字符串）或条件跳转（列表）
```

### 流程文件

| 文件 | 用途 |
|------|------|
| `flow_config/user_flows.yml` | 用户侧业务流程（订单查询、物流、退款等） |
| `flow_config/system_flows.yml` | 系统侧流程（任务启动/中断/恢复/取消、信息收集等） |

## 步骤类型

### 1. StartFlowStep (type: `start`)

流程的起始步骤，每个流程必须有且仅有一个。

```yaml
- id: start
  type: start
  next: next_step_id
```

**执行逻辑**: 直接跳转到 `next` 指向的步骤。

### 2. ActionFlowStep (type: `action`)

执行一个已注册的动作。

```yaml
- id: step_id
  type: action
  action: action_name          # 动作名称，如 action_lookup_order_status
  args:                        # 动作参数（可选）
    key: value
    # 支持 Jinja2 模板语法: {{ slots.slot_name }}
  next: next_step_id
```

**执行逻辑**: 
1. 跳转到 `next` 指向的步骤
2. 构建 `ActionCall(action_name, args)` 返回
3. `FlowExecutor` 执行 Action 后收集结果

### 3. CollectSlotStep (type: `collect`)

收集用户输入的 Slot 值。

```yaml
- id: step_id
  type: collect
  slot_name: order_number      # 要收集的 Slot 名称
  response:                    # 向用户提问的消息配置
    text: "请告诉我你的订单号。"
  next: next_step_id
  validation: "..."            # 验证条件（可选，Python 表达式）
  failure_response:            # 验证失败时的回复（可选）
    text: "输入的格式不正确，请重新输入。"
```

**执行逻辑**:

```
1. 检查 active_task.slots 中是否已有该 slot_name 的值
2. 如果没有：
   ├── 检查 focused_object 能否自动填充该 slot
   ├── 如果能 → 填充并继续
   └── 如果不能 → 启动 system_collect_information 系统流程
        ├── 使用 response.text 向用户提问
        └── 等待用户输入（action_listen）
3. 如果有值：
   ├── 检查 validation（如果存在）
   │   ├── 通过 → 继续
   │   └── 失败 → 清除 slot，使用 failure_response 提示
   └── 无 validation → 继续
```

### 4. EndFlowStep (type: `end`)

流程结束步骤。

```yaml
- id: end
  type: end
  next: []
```

**执行逻辑**:
- 如果当前是系统任务 → 结束系统任务
- 如果当前是用户任务 → 结束活跃任务（从状态中清除）

## 步骤跳转 (Links)

### 静态跳转

```yaml
next: next_step_id    # 字符串形式 → 无条件跳转
```

### 条件跳转

```yaml
next:
  - if: "slots.get('product_id')"    # 条件表达式
    then: respond                    # 满足时跳转
  - else: missing_product_context     # 不满足时跳转
```

- `if` 条件使用 Python `eval()` 执行，当前作用域包含 `slots` 和 `context`
- `else` 是可选的兜底跳转

### 条件执行流程

```
1. 遍历 conditionals 列表
2. 对每个 ConditionalLink: eval(condition) in {slots, context}
3. 如果为 True → 跳转到 target
4. 如果没有任何条件匹配 → 如果存在 FallbackLink → 跳转到 target
5. 如果没有任何匹配且没有 fallback → 报错
```

## Slot 自动填充

当 `CollectSlotStep` 需要收集信息时，系统会尝试从用户的聚焦对象(`focused_object`) 自动填充 Slot。

### 映射规则

| 聚焦对象类型 | 自动填充的 Slot |
|-------------|----------------|
| `order` | `order_number` (取 `object.id`) |
| `product` | `product_id` (取 `object.id`) |

当用户发送对象消息（如点击订单卡片）而当前正等待收集时，系统会自动完成填充，无需用户手动输入。

## 流程执行器

### `FlowExecutor.run_task(state)` 执行流程

```
run_task(state)
│
├── 获取 current_task (active_task 或 active_system_task)
├── 获取 current_flow (从 user_flows 或 system_flows)
│
├── 循环: advance_until_action(state, current_task)
│   │
│   ├── 获取当前步骤 (current_step)
│   ├── 执行步骤 (_run_step)
│   │   │
│   │   ├── START → 返回 None (继续)
│   │   ├── END → 返回 None (任务结束/系统任务结束)
│   │   ├── COLLECT → 
│   │   │   ├── 尝试填充 slot
│   │   │   ├── 成功 → 返回 None (继续)
│   │   │   ├── 失败 → 启动 CollectSystemContext → 返回 None
│   │   │   └── 验证失败 → 清除 slot → 返回 None (继续)
│   │   └── ACTION →
│   │       ├── 跳转到 next step
│   │       └── 返回 ActionCall
│   │
│   ├── 如果返回 ActionCall → 跳出循环
│   └── 如果返回 None → 继续循环
│
├── 如果有 ActionCall → action_runner.run(action_call)
│   ├── 收集 ActionResult.messages
│   └── 更新 state.set_slots(action_result.slot_updates)
│
└── 返回 bot_messages
```

### 流程完成

当流程执行到 `end` 步骤时：
- 如果是**系统任务** → 调用 `state.end_system_task()`
- 如果是**用户任务** → 调用 `state.end_active_task()`

## 系统流程

系统流程用于处理对话过程中的系统级事件，定义在 `system_flows.yml` 中：

| 流程 ID | 触发时机 | 说明 |
|---------|----------|------|
| `system_task_started` | 启动新任务后 | 告知用户任务已开始 |
| `system_task_resumed` | 恢复暂停任务后 | 告知用户继续之前的任务 |
| `system_completed` | 任务结束后 | 空操作，占位标记 |
| `system_cannot_handle` | 无法处理时 | 根据原因分发到不同分支 |
| `system_collect_information` | 需要收集信息时 | 询问用户并等待输入 |
| `system_task_interrupted` | 任务被中断时 | 告知用户当前任务被暂缓 |
| `system_task_canceled` | 任务被取消时 | 告知用户任务已取消 |

## 用户流程

用户流程定义业务功能，定义在 `user_flows.yml` 中：

| 流程 ID | 说明 |
|---------|------|
| `onboarding` | 欢迎引导，介绍助手能力 |
| `order_status_query` | 查询订单状态 |
| `logistics_tracking` | 查询物流信息 |
| `refund_request` | 提交退款申请 |
| `similar_product_recommendation` | 相似商品推荐（预留） |
| `human_handoff` | 转接人工客服 |
