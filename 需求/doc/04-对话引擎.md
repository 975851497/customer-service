# 对话引擎

## 概述

对话引擎（`DialogueEngine`）是系统的核心组件，负责处理用户消息的分发与响应生成。它通过 `DialogueEngine.process_message()` 方法接收当前对话状态和用户消息，返回处理结果。

## 引擎构建

`build_dialogue_engine()` 函数（位于 `atguigu/engine/builder.py`）是系统的**组合根（Composition Root）**，负责组装所有模块。引擎的构建过程如下：

```
build_dialogue_engine()
│
├── 加载流程定义 (YAML)
│   ├── user_flows.yml  → user_flows (FlowsList)
│   └── system_flows.yml → system_flows (FlowsList)
│
├── 组装动作系统
│   ├── ActionRegistry
│   ├── 注册内置动作 (action_listen, action_response)
│   └── 自动发现并注册自定义动作 (lookup_order_status, lookup_logistics, ...)
│
├── 构建 FlowExecutor
│   └── FlowExecutor(flows=user_flows, system_flows=system_flows, action_runner)
│
├── 构建 TaskHandler
│   └── TaskHandler(command_processor=CommandProcessor(), flow_executor)
│
├── 构建知识模块
│   ├── KnowledgeProviderRegistry
│   │   ├── ProductAPIProvider("api.product")
│   │   ├── OrderAPIProvider("api.order")
│   │   ├── FAQProvider("faq.default")
│   │   └── RAGProvider("rag.default")
│   ├── KnowledgeResponder(llm, prompt_loader)
│   └── KnowledgeHandler(intents=KNOWLEDGE_INTENTS, registry, responder)
│
├── 构建闲聊模块
│   └── ChitchatHandler(ChitchatResponder(llm, prompt_loader))
│
├── 构建澄清模块
│   └── ClarifyResponder(llm, prompt_loader)
│
├── 构建规划模块
│   ├── TurnPlanner(llm, prompt_loader)
│   └── TurnPlanValidator()
│
└── 返回 DialogueEngine
```

## 处理流程

### `process_message(state, user_message)` 详解

```
┌─────────────────────────────────────────────────────────────────┐
│ process_message(state, user_message)                             │
│                                                                  │
│  ┌─────────────────────────────────────────────┐                │
│  │ 1. _prepare_session(state)                  │                │
│  │    - 当前无会话 → 创建新会话                  │                │
│  │    - 当前会话超过1小时未活动 → 关闭并创建新会话 │                │
│  │    - 正常 → 复用当前会话                      │                │
│  └─────────────────┬───────────────────────────┘                │
│                    ▼                                             │
│  ┌─────────────────────────────────────────────┐                │
│  │ 2. _begin_turn(state, user_message)          │                │
│  │    - 创建新的 Turn                           │                │
│  │    - 设置 state.pending_turn                 │                │
│  └─────────────────┬───────────────────────────┘                │
│                    ▼                                             │
│  ┌─────────────────────────────────────────────┐                │
│  │ 3. 消息类型判断                              │                │
│  │                                              │                │
│  │  用户消息类型？                               │                │
│  │  ├── OBJECT → _handle_object_message()       │                │
│  │  └── TEXT → _handle_text_message()           │                │
│  │                                              │                │
│  │  3.1 OBJECT 处理                             │                │
│  │  - 检查 active_system_task 是否为 collect    │                │
│  │  - 如果是，自动将对象映射到对应 Slot          │                │
│  │  - 调用 task_handler.handle()                │                │
│  │                                              │                │
│  │  3.2 TEXT 处理                               │                │
│  │  - TurnPlanner.predict() → TurnPlan          │                │
│  │  - TurnPlanValidator.validate()              │                │
│  │  - 按预测结果分发                             │                │
│  │    ├── task → task_handler.handle()          │                │
│  │    ├── knowledge → knowledge_handler.handle() │                │
│  │    ├── chitchat → chitchat_handler.handle()  │                │
│  │    └── clarify → clarify_responder.respond() │                │
│  └─────────────────┬───────────────────────────┘                │
│                    ▼                                             │
│  ┌─────────────────────────────────────────────┐                │
│  │ 4. commit_pending_turn(state)               │                │
│  │    - 将 pending_turn 添加到当前会话          │                │
│  │    - 清除 pending_turn                      │                │
│  │    - 返回 ProcessResult                     │                │
│  └─────────────────────────────────────────────┘                │
└─────────────────────────────────────────────────────────────────┘
```

## 会话管理

### 会话生命周期

```python
# 状态判断逻辑
if state.current_session is None:
    # 无会话 → 创建新会话
    state.start_session()
    
elif 当前会话已超过 1 小时无活动:
    # 会话超时 → 关闭旧会话，创建新会话
    state.close_current_session()
    state.reset_runtime_state_for_new_session()
    state.start_session()
    
else:
    # 复用当前会话
    pass
```

- 会话超时时间硬编码为 **1 小时**（3600 秒）
- 新会话创建时会重置运行时状态（清除活跃任务、聚焦对象等）

## 消息路由

### 文本消息

文本消息经过完整的 Turn Planning 流程：

1. **TurnPlanner** 调用 LLM，传入以下上下文：
   - 对话历史（最近的对话回合）
   - 可用的业务流程列表
   - 当前活跃任务信息
   - 被暂停的任务信息
   - 用户聚焦对象信息
   - 可用的知识意图列表
   
2. LLM 输出结构化的 **TurnPlan** JSON

3. **TurnPlanValidator** 验证：
   - 恰好有一个赛道被选中
   - 如果选中 task 赛道，必须有命令
   - 如果选中 knowledge 赛道，必须有意图
   - 如果意图需要聚焦对象但未提供，标记为需澄清

### 对象消息

当用户发送结构化对象（如订单卡片）时：
- 跳过 Turn Planner 的 LLM 调用
- 直接检查当前 `active_system_task` 是否是 `system_collect_information`
- 如果是，自动将对象映射到当前正在收集的 Slot
- 映射规则：`object.type == "order"` → `order_number` slot；`object.type == "product"` → `product_id` slot

## 任务中断与恢复

系统支持任务中断和恢复的对话管理：

```
用户: "帮我查一下订单12345的状态"
  → 启动 order_status_query 流程（活跃任务）

用户: "等一下，先帮我查一下物流单号67890"
  → LLM 规划为新的 logistics_tracking 流程
  → CommandProcessor 检测到活跃任务存在
  → 中断当前任务，压入 paused_tasks 栈
  → 启动新任务
  → 启动 InterruptedSystemContext 系统流程

用户: "回到刚才的订单查询"
  → LLM 规划 ResumeFlowCommand
  → 从 paused_tasks 弹出对应任务恢复
  → 启动 ResumedSystemContext 系统流程
```
