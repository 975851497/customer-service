# 知识问答模块

## 概述

知识问答模块（Knowledge Module）负责识别用户的查询意图，从多个数据源检索相关信息，并生成自然语言回复。当 `TurnPlanner` 预测当前用户消息属于知识查询赛道时，由 `KnowledgeHandler` 处理。

## 处理流程

```
KnowledgeHandler.handle(intents, state)
│
├── 1. 去重：收集所有 intents 对应的 provider_ids 并去重
│
├── 2. 并行检索：对每个 provider_id 调用对应的 KnowledgeProvider
│   ├── ProductAPIProvider  → 查询商城商品 API
│   ├── OrderAPIProvider    → 查询商城订单+物流 API
│   ├── FAQProvider         → 查询 FAQ 知识库
│   └── RAGProvider         → 查询 RAG 知识库
│
├── 3. 合并：汇总所有 Provider 返回的 KnowledgeChunk
│
└── 4. 生成回复：KnowledgeResponder.respond()
    ├── 构建提示词（用户消息 + 对话历史 + 知识内容）
    ├── 调用 LLM
    └── 返回 BotMessage
```

## 知识意图 (KnowledgeIntent)

### 意图定义

知识意图用来描述用户希望查询的信息类型，是 LLM 在 Turn Planning 阶段进行意图匹配的依据。

```python
class KnowledgeIntent:
    id: str                     # 唯一标识
    description: str            # 意图描述（用于 LLM 匹配）
    provider_ids: list[str]     # 需要调用的知识提供者
    requires_object: bool       # 是否需要聚焦对象
```

### 预定义意图

| 意图 ID | 描述 | 提供者 | 需要对象 |
|---------|------|--------|---------|
| `product_info` | 用户想了解商品的具体信息，如规格、价格、库存等 | `api.product` | ❌ |
| `order_info` | 用户想了解订单的具体信息，如订单状态、金额、收货地址等 | `api.order` | ❌ |
| `refund_policy` | 用户想了解退款相关的政策 | `faq.default` | ❌ |
| `return_policy` | 用户想了解退换货相关政策 | `faq.default` | ❌ |
| `shipping_policy` | 用户想了解配送/运费相关政策 | `faq.default` | ❌ |
| `platform_rule` | 用户想了解平台规则 | `faq.default` | ❌ |
| `general_ecommerce_info` | 用户想了解通用电商信息 | `faq.default` + `rag.default` | ❌ |

## 知识提供者 (KnowledgeProvider)

### 接口定义

```python
class KnowledgeProvider(ABC):
    provider_id: str
    
    @abstractmethod
    async def retrieve(self, state: DialogueState) -> list[KnowledgeChunk]:
        """检索知识块"""
        ...

@dataclass
class KnowledgeChunk:
    content: str        # 知识内容文本
    source: str | None  # 来源标识
```

### 内置提供者

#### ProductAPIProvider (`api.product`)

从商城 API 查询商品信息。

```
请求: GET {COMMERCE_API_BASE_URL}/api/product/{product_id}
        其中 product_id 从 focused_object 获取

返回: 商品信息 → KnowledgeChunk
```

- 需要用户当前有聚焦的商品对象
- 如果 `state.focused_object` 为空，返回空结果

#### OrderAPIProvider (`api.order`)

从商城 API 查询订单及物流信息。

```
请求: 并行调用
  - GET {COMMERCE_API_BASE_URL}/api/order/{order_id}
  - GET {COMMERCE_API_BASE_URL}/api/logistics/{order_id}

返回: 订单信息 + 物流信息 → KnowledgeChunk
```

- 需要用户当前有聚焦的订单对象
- 如果 `state.focused_object` 为空，返回空结果

#### FAQProvider (`faq.default`)

FAQ 知识库提供者（当前为占位实现）。

- 当前行为：始终返回空列表 `[]`
- 预期未来接入：基于关键词匹配或向量检索的 FAQ 知识库

#### RAGProvider (`rag.default`)

RAG 检索增强生成提供者（预留）。

- 当前行为：始终返回空列表 `[]`
- 预期未来接入：基于向量数据库的检索增强生成

## 知识响应器 (KnowledgeResponder)

将检索到的知识块合并后，通过 LLM 生成自然的回复。

### 提示词模板 (`knowledge_respond.jinja2`)

```
你是一个中文电商客服助手。
请基于以下对话历史和知识内容，回复用户的问题。
如果知识内容不足以回答问题，请如实告知用户。

对话历史：
{{ history }}

用户问题：{{ user_message }}

相关知识内容：
{{ knowledge_content }}

请生成回复：
```

### 响应生成

```python
class KnowledgeResponder:
    async def respond(self, user_message, history_text, knowledge_content) -> BotMessage:
        prompt = self._render_prompt(
            user_message=user_message.text,
            history=history_text,
            knowledge_content=knowledge_content  # 所有 KnowledgeChunk.content 的拼接
        )
        llm_response = await self.llm.ainvoke(prompt)
        return BotMessage(text=llm_response.content)
```
