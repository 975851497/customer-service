# 闲聊与澄清模块

## 闲聊模块 (Chitchat)

### 概述

当 `TurnPlanner` 判断用户消息属于非任务型对话（问候、日常聊天等）时，交由闲聊模块处理。闲聊模块通过 LLM 生成自然、友好的回复。

### 处理流程

```
ChitchatHandler.handle(state, user_message)
│
└── ChitchatResponder.respond(user_message, history_text)
    │
    ├── 加载提示词模板 (chitchat_respond.jinja2)
    ├── 渲染提示词（对话历史 + 用户消息）
    ├── 调用 LLM
    └── 返回 BotMessage
```

### 提示词模板 (`chitchat_respond.jinja2`)

```
你是一个中文电商客服助手，可以回答用户的问候和日常聊天。
请根据对话历史和用户消息，生成友好、自然的回复。

对话历史：
{{ history }}

用户：{{ user_message }}

回复：
```

### 闲聊触发场景

| 用户输入示例 | 预期行为 |
|-------------|----------|
| "你好"、"在吗" | 问候回应 |
| "谢谢"、"好的" | 礼貌回应 |
| "今天天气不错" | 日常聊天回应 |
| 非电商相关的一般性提问 | 友好回应，引导回电商主题 |

## 澄清模块 (Clarify)

### 概述

当 `TurnPlanner` 的预测结果不满足验证规则，或者用户的意图不够明确时，由澄清模块生成澄清回复，引导用户提供更清晰的信息。

### 触发场景

| 澄清原因 | 说明 | 示例场景 |
|----------|------|----------|
| `MISSING_TRACK` | LLM 没有选择任何赛道 | 用户输入模糊，无法归类 |
| `MULTIPLE_TRACKS` | LLM 同时选择了多个赛道 | 用户一句话包含多种意图 |
| `MISSING_TASK_COMMANDS` | 任务赛道缺少命令 | 判断为任务但未指定具体命令 |
| `MISSING_KNOWLEDGE_INTENT` | 知识赛道缺少意图 | 判断为知识查询但未指定意图 |
| `MISSING_FOCUSED_OBJECT` | 需要对象但未提供 | 知识查询需要商品/订单对象 |
| `OBJECT_REQUIRES_INTENT` | 对象消息但缺少意图 | 用户发了对象但未说明意图 |

### 处理流程

```
ClarifyResponder.respond(state, reason)
│
├── 1. 根据 reason 选择预定义的 clarify_message
│
│   MISSING_TRACK / MISSING_TASK_COMMANDS:
│     → "我没太理解你的意思。你可以告诉我你想查订单、查物流、了解商品，还是申请退款吗？"
│
│   MULTIPLE_TRACKS:
│     → "我注意到你似乎想同时处理几件事。请先告诉我你最想先处理哪一个？"
│
│   MISSING_KNOWLEDGE_INTENT:
│     → "你想了解关于商品的哪些信息？比如规格、价格或者库存。"
│
│   MISSING_FOCUSED_OBJECT:
│     → "你需要先选择一个商品或订单，我才能帮你查询相关信息。"
│
│   OBJECT_REQUIRES_INTENT:
│     → "你发来的这个信息我看到了。你想对它进行什么操作呢？"
│
├── 2. 调用 LLM 对 clarify_message 进行自然语言改写
│   （使回复更自然、避免生硬）
│
└── 3. 返回 BotMessage
```

### 提示词模板 (`clarify_respond.jinja2`)

```
你是一个中文电商客服助手。
请基于建议回复，生成一句自然友好的回复，保持原意，不要扩写。

建议回复：{{ clarify_message }}

改写后的回复：
```

### 验证与澄清的完整流程

```
TurnPlanner.predict()
│
├── 返回 TurnPlan
│
└── TurnPlanValidator.validate(turn_plan)
    │
    ├── 有效 → 按赛道分发处理
    │
    └── 无效 → ClarifyResponder.respond(reason)
         │
         └── 返回澄清回复（引导用户重新表述）
```

### "无法处理" 的分支流程

当系统无法处理用户请求时，`TurnPlanner` 会规划一个不能处理的流程，由 `system_cannot_handle` 系统流程处理。根据 `context.reason` 分为四种情况：

| 原因 | 回复模板 |
|------|----------|
| `clarification_rejected` | "看来我刚才理解偏了。你可以重新说一下你想查订单、查物流，还是申请退款吗？" |
| `not_supported` | "我理解你的意思，不过这个能力目前还没有接入。" |
| `no_relevant_answer` | "我暂时没有查到合适的信息。你可以换个说法，或者告诉我更具体一点的商品或订单信息。" |
| 其他 (默认) | "抱歉，我这边没有完全听明白。你可以再具体说一下你想处理什么电商问题吗？" |

所有分支均使用 `action_response` 的 `rephrase` 模式，先渲染建议文本，再经过 LLM 改写后输出。
