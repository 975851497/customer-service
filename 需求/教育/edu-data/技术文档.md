# edu-data 技术文档

本文档总结 `edu-data` 项目的目录结构、模块职责与技术架构，便于快速理解代码组织方式。业务字段、表结构与 API 细节请参阅同级 [README.md](./README.md)。

---

## 1. 项目定位

`edu-data` 是在线教育业务的数据与 API 工程，包含三部分能力：

| 能力 | 说明 |
|------|------|
| 数据库 Schema | 通过 `sql/edu.sql` 定义 67 张业务表 |
| 数据生成 | 按 7 层依赖顺序批量造数，支持 smoke / full 两种规模 |
| REST API | 基于 FastAPI 暴露 12 组业务接口，供智能客服等外部系统查询与操作 |

技术栈：Python 3.12、FastAPI、PyMySQL / asyncmy、SQLAlchemy（仅用于 init_db 反射）、uv 包管理、MySQL 8.0。

## 3. 根目录文件

| 文件 | 职责 |
|------|------|
| `init_db.py` | 异步初始化 MySQL：检测/删除/创建库 → 执行 `sql/*.sql` → 可选 sqlacodegen 生成 ORM 模型 |

| `.python-version` | 指定 Python 3.12 |
| `Dockerfile` | 基于 `python:3.12-slim`，用 uv 安装依赖并启动 uvicorn |
| `README.md` | 业务概述、表定义、数据生成规则、接口定义（主文档） |

## 4. `app/` — API 应用层

FastAPI 服务入口，采用「路由 + 原生 SQL」的轻量架构，不依赖 ORM 实体层。

```
app/
├── main.py           # 应用入口，注册 12 个 router 与全局异常处理
├── config.py         # 读取 .env，暴露 DB_CONFIG、APP_PORT 等
├── database.py       # PyMySQL 连接池封装：fetch_one / fetch_all / execute
├── dependencies.py   # FastAPI 依赖：通过 X-User-Id 请求头识别当前用户
├── errors.py         # AppError 及 HTTP 状态码辅助函数
├── response.py       # 统一响应格式 { code, message, data }
├── utils.py          # 通用工具函数
└── routers/          # 按业务域拆分的路由模块
    ├── users.py          # 用户信息与学习档案
    ├── courses.py        # 课程系列与班次查询
    ├── favorites.py        # 收藏
    ├── consultations.py    # 咨询
    ├── coupons.py          # 优惠券
    ├── cart.py             # 购物车
    ├── orders.py           # 订单
    ├── payments.py         # 支付与退款
    ├── enrollments.py      # 报名关系与学习中心
    ├── study.py            # 课次、视频、作业、考试
    ├── interactions.py     # 互动与评价
    └── tickets.py          # 工单与售后服务
```

**设计要点：**

- 所有业务路由统一前缀 `/api/v1`，OpenAPI 文档在 `/docs`。
- 身份认证为演示级实现：需用户身份的接口通过请求头 `X-User-Id` 传入平台用户 ID，并在 `sys_user` 表中校验。
- 响应体统一为 `{ "code": 0, "message": "ok", "data": ... }`；业务错误通过 `AppError` 映射为对应 HTTP 状态码。
- 数据库访问全部走 `database.py` 中的同步 PyMySQL 辅助函数，SQL 写在各 router 内。

## 5. `generate/` — 数据生成层

按业务依赖关系分 7 层顺序造数，每层对应一个 Generator 类。

```
generate/
├── main.py              # CLI 入口：--profile smoke|full，--layers 1,2,...,7
├── config.py            # LAYERS 表清单、GENERATION_PROFILES 规模参数
├── db.py                # 生成器专用 PyMySQL 封装（含 KILL CONNECTION 中断支持）
├── insert_support.py    # 批量 INSERT 语句构建
├── progress.py          # Rich 进度条与控制台输出
└── layers/
    ├── base.py          # BaseGenerator 抽象基类
    ├── seed_importer.py # CSV 种子导入与业务编码 → 主键映射
    ├── validations.py   # Layer7 验收校验规则
    ├── layer1.py        # 基础维度与组织主数据
    ├── layer2.py        # 课程供给主数据
    ├── layer3.py        # 题库、营销与转化准备
    ├── layer4.py        # 交易与履约闭环
    ├── layer5.py        # 学习、互动与服务过程
    ├── layer6.py        # 经营衍生结果
    └── layer7.py        # 最终验收（调用 validations）
```

**七层数据依赖：**

| Layer | 名称 | 核心表（节选） |
|-------|------|----------------|
| 1 | 基础维度与组织主数据 | `dim_*`、`sys_user`、`org_*`、`staff_profile`、`student_profile` |
| 2 | 课程供给主数据 | `series`、`series_cohort`、`series_cohort_session`、`session_*` |
| 3 | 题库、营销与转化准备 | `question_bank`、`coupon`、`series_*_log`、`shopping_cart_item`、`consultation_record` |
| 4 | 交易与履约闭环 | `order`、`payment_record`、`refund_request`、`student_cohort_rel` |
| 5 | 学习、互动与服务过程 | `session_attendance`、`session_video_play`、`cohort_discussion_*`、`service_ticket` |
| 6 | 经营衍生结果 | `teacher_compensation_*`、`channel_commission_*`、`risk_*`、`ugc_moderation_task` |
| 7 | 最终验收 | 无写表，执行 `validations.py` 中的数据一致性检查 |

**生成规模（profile）：**

- `smoke`：约 800 用户，适合本地快速验证（`make smoke`）。
- `full`：约 10 万用户、8 万订单，适合压测与完整联调（`make gen`）。

Layer1 会先通过 `seed_importer.py` 导入 `seeds/` 下的 CSV，再程序化生成用户、组织等大量数据；Layer2 起主要基于已有主数据按模板扩展。

## 7. `sql/` — 数据库 Schema

| 文件 | 职责 |
|------|------|
| `edu.sql` | 完整 DDL，共 67 张表；文件名 `edu` 即数据库名 |
| `.sqlfluff` | SQL 格式化 / Lint 配置 |

`init_db.py` 会扫描 `sql/*.sql`，每个 `.sql` 文件对应一个独立数据库（当前仅 `edu`）。

## 8. `tests/` — 集成测试

基于 pytest + FastAPI TestClient，依赖已造数的真实数据库。

| 文件 | 覆盖范围 |
|------|----------|
| `conftest.py` | TestClient  fixture、`SampleData` 辅助类（从库中取样例用户/课程/订单） |
| `test_users_and_courses.py` | 用户档案、课程查询 |
| `test_conversion.py` | 收藏、咨询、领券、购物车等转化链路 |
| `test_orders_and_payments.py` | 下单、支付、退款 |
| `test_learning_and_interactions.py` | 学习过程、评价 |
| `test_tickets.py` | 工单与满意度 |

运行前需先 `make smoke` 或 `make gen` 确保库中有数据。

## 9. `docker/` — 容器编排

```
docker/
└── docker-compose.yaml
```

定义两个服务：

- **mysql**：MySQL 8.0，端口 3306，utf8mb4，持久化卷 `mysql-data`。
- **api**：基于项目根目录 `Dockerfile` 构建，端口 8000，依赖 MySQL 健康检查后启动。

典型用法：仅启动数据库 `docker compose up -d mysql`，API 在宿主机用 `make run` 调试；或 `docker compose up -d` 一键启动全套。

## 10. 运行流程与模块关系

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  sql/edu.sql │ ──► │  init_db.py  │ ──► │  MySQL (edu 库) │
└─────────────┘     └──────────────┘     └────────┬────────┘
                                                     │
┌─────────────┐     ┌──────────────┐                │
│ seeds/*.csv  │ ──► │ generate/    │ ───────────────┤
└─────────────┘     │ main.py      │                │
                    └──────────────┘                │
                                                     ▼
                    ┌──────────────┐     ┌─────────────────┐
                    │  app/main.py │ ◄── │  tests/         │
                    │  (FastAPI)   │     │  (集成测试)      │
                    └──────────────┘     └─────────────────┘
```

**推荐启动顺序：**

1. 配置 `.env` 并启动 MySQL（本地或 Docker）。
2. `make init_db` 或 `uv run init_db.py` — 建库建表。
3. `make gen` / `make smoke` — 分层造数。
4. `make run` — 启动 API，访问 `http://127.0.0.1:8000/docs`。
